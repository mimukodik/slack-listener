# Principles

How slack-listener is designed, written and tested. It follows [Tiger Style](https://github.com/tigerbeetle/tigerbeetle/blob/main/docs/TIGER_STYLE.md) and deterministic simulation testing as TigerBeetle, FoundationDB and Antithesis practise it, carried over to TypeScript and [Effect](https://effect.website). [RULES.md](RULES.md) says what the tool does; this file says how it is built. Each principle has a stable id, how it is enforced, and whether the code holds it today. A principle the code does not yet hold is a target, and the work towards it is planned, not hidden.

## Manifesto

**Safety, then performance, then developer experience, in that order.** A message that should not reach a session must never reach it, and one that should must not be lost. Only then does speed count, and only then comfort.

**The simulator runs the program, not a model of it.** Production and simulation start the same Effect program. The simulator swaps only the world underneath: the clock, the scheduler, randomness, the network, the socket, the session and the disk. Whatever runs only in production is untested.

**Every run is a seed.** All nondeterminism comes from one stream of choices. The same choices give the same run, down to the order of fibers and the millisecond of every timer, so a failure is found once and replayed forever.

**Assertions are the oracle.** The code states what must be true and what must never happen, and stops when either breaks. The simulator multiplies every assertion by millions of executions; a missing assertion is a bug the simulator cannot see.

**Everything has a limit.** Every queue, cache, retry and wait is bounded, and every request has a deadline. Unbounded is a bug that has not happened yet.
