# Listener maintenance pilot, protocol 1.1

## Decision fixed before implementation

The headline hypothesis is at least 30% less elapsed agent time per accepted Zig maintenance change than Rust with comparable observed correctness. TypeScript/Effect is the third arm, reported on the same tasks. The 30% threshold and sample sizes here are experiment design choices. A pilot can justify replication on another workload. It cannot establish general memory safety or choose a platform for desktop, mobile and web.

| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Accepted changes per agent-hour | Count accepted exact-head submissions. Divide by the sum of charged seconds over **every scheduled attempt** and multiply by 3600. From prompt delivery to final submission include reading, model inference, tools, builds, retries and the public gate.                              | Primary time measure. Report numerator, denominator and all individual rows. Zero successes has zero throughput.                                                    |
| Correct submissions             | An independent evaluator runs the frozen public and held-back checks against the first final commit, once. Count passes divided by all scheduled attempts. Retain failure classes and replay inputs.                                                                                   | Quality gate. A timeout, abandonment, broken build, failing check or missing submission fails. Passing means the observed checks passed.                            |
| Cost and cause                  | Record model input, cached input and output tokens from the agent usage receipt where available; record uninterrupted elapsed compiler/check wait from tool timestamps, peak memory with units plus measurement method, whether the ordinary local build outputs were already present. | Diagnostic only. Model tokens are not dollars without a pinned price. Parallel command durations must be unioned for elapsed wait. A missing counter stays missing. |

## Freeze and run

1. Seal this protocol in Git before starting the ports. Maintain a separate construction log. Before **any scored maintenance run**, freeze all three baseline commits, shared entry point and gates. Run the baseline gate on each. Use synthetic Slack and session peers plus a temporary state directory. The same runner must exercise the production paths for each language. Record the rule-to-check map and prove the oracle detects planted wrong behavior before removing those mutations.
2. Select three previously unseen product edits before observing any language response: one decision rule, one restart/recovery interaction, one deferred I/O/ownership interaction. Have a coordinator who will not implement them seal the exact three prompts, held-back inputs, expected outputs and scoring code. Publish SHA-256 commitments in a dated registration commit before dispatch. Give implementers only their own prompt and public checks. Reveal the sealed materials with results. If an agent saw a held-back task previously, record contamination and do not substitute another task after seeing outcomes.
3. Run two independent repetitions per task and language, 18 planned attempts. Use clean worktrees at each baseline, fresh agents, identical model/build, reasoning setting, budget, runner class and access to the same public specification. No reference solution, prior session, counterpart implementation or cross-arm hints in the scored workspaces. Rotate order by task (TS/Rust/Zig; Rust/Zig/TS; Zig/TS/Rust), reverse for repetition two. Run timed comparisons without contested hosts. Parallel construction in two panes is outside this cohort.
4. Measure an ordinary local maintenance edit. Before timing, run each arm's documented baseline check once in its own worktree and keep its normal local build outputs for the edit. Record the command and initial setup time separately. Use the same preparation procedure for every repetition. Shared-cache configuration, transfers and hit rates are outside the study.
5. Allow 45 minutes per attempt. A final submission stops the agent timer. Charge actual elapsed time to a passing submission and the full 45 minutes to every failure, so early abandonment cannot improve throughput. Publish actual elapsed separately. One final submission per attempt; invisible evaluator feedback and no repairs after submission. A predetermined host outage or provider failure invalidates the **whole matched three-language block**, kept in the ledger; reschedule that block once before unblinding. Unclassifiable failures count. Never reroll a bad patch.
6. Freeze the complete run roster before dispatch. Store monotonic start/end observations, UTC timestamps, prompt digest, exact baseline and candidate commits, toolchain versions and local preparation commands, exit codes, gate report hashes and usage sources. Keep all rows, partials, failures and stop reasons. Archive sanitized commands, small fixtures and machine-readable results. Do not publish session transcripts or environment dumps. Changes to rules, gates, or scoring get a new protocol revision with rationale; report original outcomes first.

## Evaluation

A pass for the pilot requires all three task families represented, all scheduled attempts accounted for, Zig accepting at least as many as Rust, zero observed critical Zig failures (lost accepted delivery, sender isolation violation, incorrect persisted acknowledgement, or memory-safety failure), and time per accepted change at most 0.70 times Rust's. At zero Rust accepts the ratio is undefined and there is no speed verdict. Otherwise report misses and ties as measured. Report per-task pairs, medians and the six attempts per language; make no population-level noninferiority claim from this pilot. For example, six Zig accepts in 2.1 charged hours and six Rust accepts in 3.0 gives 0.70, exactly on the threshold. Any critical Zig failure still prevents adoption on this evidence.

Assess reuse on fresh desktop, mobile and browser workloads later. For a WASM or mobile claim require the same core to compile for the actual target and replay an observable fixture in that host. For JS/Effect record engine and host adapters. Network, filesystem and UI adapters, transfer costs, binary sizes, peak memory and runtime performance belong to separately registered target studies. A server listener is evidence for event-driven systems work only.

Use `python3 score.py ledger.jsonl` on the independent evaluator's final ledger. Each line has arm (effect, rust, zig), task (decision, recovery, deferred-io), rep (1 or 2), elapsed_seconds, outcome (pass, fail, timeout, abandoned or missing), critical_failure and receipt_sha256. Digest the accompanying public evaluator receipt. A missing submission still gets an evaluator receipt and a row. The scorer refuses incomplete or duplicated cohorts. Keep invalidated blocks and original receipts beside the final ledger. Check the digest against its actual file when assembling the ledger. The script calculates scores; the independent evaluator owns acceptance and receipt verification.
