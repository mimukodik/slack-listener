## 2026-11-23: swarm testing, measured and dropped (BER-2419)

Method 3 of the experiment. Swarm testing (Groce et al., ISSTA 2012; FoundationDB's and TigerBeetle's simulators do the same) switches a random subset of action kinds and fault classes off for each run, drawn from the seed, so each run goes deeper into fewer behaviours. The question was whether that finds our bugs in fewer runs. The bar, fixed before measuring: a predeclared mutant's kill curve improves at equal runtime, with baseline coverage kept; where it does not, the code goes and the numbers stay. It did not, in either simulator, and the code is gone.

- **The mask.** With `--swarm`, a sampled run drew its mask from its own choice stream before it started: each kind and class on with probability 1/2, at least one action kind on. The listener had 21 (six world actions: post, reply, edit, remove, a post elsewhere, noise; the session's `done`; and 14 fault classes: crash, disconnect, sleep, failing session writes, failing API, a crash after a done, failed connection opens, malformed API answers, frames, envelopes and session lines, unreadable posts, duplicate envelopes, replies under unreadable parents). The hub had 19 (its 12 call kinds; waits, repeated calls, a key shared with another principal, outsider bearers, and crashes by timer, outside and inside a transaction). A swarm run kept act's and plan's weights among what was left on. Plain runs drew nothing and took every branch as before: the listener's 2000-seed hash stayed `c837976d…3438c4` (every seed's line identical), the hub's 500 seeds hashed the same as on main, and depth 7 gave main's 680,613 sequences, 0 violations and eight counters. Same seed, same mask, same run: checked on 20 listener and 10 hub seeds, and by a spec in each simulator. The code, about 165 lines, is commit ce030f8 on this branch, for anyone who wants to repeat the measurement.
- **The mutants, declared first.** Fourteen for the listener and seven for the hub, chosen from the planted bugs recorded above and new ones, the hard ones first: those plain runs kill in under 10% of runs. Two listener mutants killed nothing in 10,000 plain runs, because the sampled world never reaches their code: a live message older than the catch-up's start that was not dropped (only the R21 resend case reaches it, and the fake's unreadable messages never decode live either), and pruning with a shorter horizon (no run lasts the 24 simulated hours before anything is pruned). Swarm only switches behaviours off, so it cannot reach them either. Both were replaced, before any swarm code existed, by two that the world does reach (L13, L14).
- **The method.** Each mutant was copied aside, planted, run, restored with `cp` and checked with `cmp`. Both modes ran the same seeds: listener seeds 1 to 10,000 of 120 actions, as five offsets of 2,000 (CI's pass); hub seeds 1 to 2,500 of 80 calls, as five offsets of 500. A swarm run cost less than a plain one (listener about 21 ms against 26 to 40 ms; hub about 100 to 185 ms against 130 to 320 ms, on a shared Mac), more than 10% apart, so the comparison is at equal runtime: kills per second of summed run time, plain against swarm, with the range over the five offsets. The hub's run times varied by up to 2x between plain measurements; the verdict does not rest on them, because swarm's kill rate per run is lower by more than its cost saving for every hub mutant.

- **Coverage on the correct code.** Per run, swarm lowered 27 of the listener's 28 counters (disconnects alone rose, by 36%) and 13 of the hub's 16 (calls equal; event reads up 13%). Per second of run time, which credits swarm's cheaper runs, it still lowered 15 of the listener's 28, the deepest the most: replies under unreadable parents to 0.31, malformed answers to 0.36, unreadable messages in a catch-up page to 0.49, done marks to 0.60. In the hub, 10 of 16, input round trips and wrong answerers to 0.26, stale holders refused to 0.31.
- **Why it loses here.** The hard bugs need several behaviours at once: L1 and L2 need a done mark, failing reaction calls and three failures in a row; L10 a done mark racing the delivered event; L7 edits with reordered or duplicated envelopes; the hub's lease mutants claims, input requests, answers and waits in one run. A mask that keeps each with probability 1/2 keeps all of three only an eighth of the time, and nothing here suppresses anything else, which is where swarm wins (Groce's case: a stack's pops keep it from ever filling). One mutant, L3, did better at equal runtime, about 28%, because a run with fewer behaviours is cheaper and its bug needs only bad session lines; per run it was even (8.65% against 8.28%). The hardest mutants went the other way: L10 from 10 kills to 1, L5 from 12 to 5.
- **The decision.** Dropped in both simulators, by the bar: no hard mutant's kill curve improved with coverage kept; the one that improved did so while 15 counters fell. The swarm code is removed, so main carries no option nobody runs, and `src/` is byte-identical to main. The checks: lint clean, 139 tests pass and 4 todo, `sim 2000 120` 0 failures with the hash `c837976d…3438c4`, `exhaustive 7` 680,613 sequences and 0 violations with the eight counters equal to main's, `sim:hub 500 80` 0 failures, `sim:hub:replay` 0 failures. Raw rows for every run are kept with the measurement, outside the repository. What would make it worth another look: a fault that hides others (an outage so frequent that nothing reaches catch-up, a crash rate that cuts runs short) or mutants that need one behaviour run long; a smaller mask (each feature off with probability 1/8) is the cheap variant to try first.
- **Principles.** `the-end-is-declared-before-the-start`: the bar and the mutants were written down before the first swarm run, and the result is held to them, not to the one row that won. `experiment-beats-research`: the literature says swarm usually helps; ten minutes of runs say it does not here. `cheapest-work-is-work-not-done`: an option CI does not run is code to keep in step for nothing, so it goes. `every-guardrail-names-its-failure`: each mutant names the rule it breaks, and the two that no run could reach were replaced, not counted as wins for either mode.
